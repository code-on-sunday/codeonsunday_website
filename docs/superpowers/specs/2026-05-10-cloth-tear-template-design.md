# Cloth-Tear Template — local-first proof

## Goal

Refactor the repo so the visible "pages" are authored as HTML + assets in a folder per site, snapshotted to PNG via Playwright, and consumed by a content-agnostic runtime. Dropping a new `sites/<name>/` folder into the repo and visiting `/<name>` produces a working tearable site without touching `src/main.js`.

This is the foundation for a hosted v2 (Cloudflare Browser Rendering + R2 + KV + short-link viewer). v1 is entirely local; v2 swaps the snapshot step from local Playwright to the cloud API.

## Non-goals (v1)

- Online editor, render service, or share-link flow.
- Customization knobs (cloth physics, palette, sparkle density). Hard-coded to today's values.
- Live HTML *on the cloth* — cloth pages are PNG snapshots. The final page is real HTML in an iframe.
- Authentication, accounts, custom domains, analytics.

## Repo layout

```
cloth-tear/

    main.js                 # generalized runtime
  sites/
    trung/                  # current site, ported to HTML
      manifest.json
      pages/
        01-hello.html
        02-hanoi.html

        05-side-projects.html
        06-3-lines.html
        07-real-people.html
        08-friends.html
      assets/
        style.css
        photos/...
      snapshots/            # generated by scripts/snapshot.mjs (committed)
        01-hello.portrait.png
        01-hello.landscape.png
        ...
  scripts/
    snapshot.mjs            # Playwright HTML→PNG snapshotter
  vite.config.js
  wrangler.jsonc
```

`snapshots/` is committed to git, not gitignored. Production deploys are static-asset uploads; running Playwright in the Cloudflare build step would be heavyweight and slow. Local dev regenerates snapshots on demand. Each PNG is small (tens of KB after compression), so the repo footprint stays modest.

## Manifest format

```json
{
  "title": "Trung — tear to read",
  "pages": [
    { "html": "pages/01-hello.html" },
    { "html": "pages/02-hanoi.html" },
    { "html": "pages/03-badminton.html" },
    { "html": "pages/04-grew-up.html" },
    { "html": "pages/05-side-projects.html" },
    { "html": "pages/06-3-lines.html" },
    { "html": "pages/07-real-people.html" },
    { "html": "pages/08-friends.html", "final": true }
  ]
}
```

Rules:
- The last entry must have `"final": true`. Exactly one final page per site in v1.
- Snapshot filenames are derived from `html`: `pages/01-hello.html` → `snapshots/01-hello.portrait.png` and `snapshots/01-hello.landscape.png`. No per-page filename overrides.
- Page count: 2–10 inclusive. Below 2 there's nothing to tear; above 10, the UX gets tedious.

## Routing

Path-based. `/` and `/trung` both render the trung site (the default — no redirect, both URLs render the same content). `/<sitename>` renders `sites/<sitename>/`. Unknown sitenames render a 404 page.

**Local (Vite):** middleware in `vite.config.js` rewrites non-file, non-reserved paths to `/index.html`. Reserved prefixes: `/src/`, `/sites/`, `/node_modules/`, `/@`. Files (anything matching `/\.[a-z0-9]+$/i`) are served as-is.

```js
// vite.config.js
configureServer(server) {
  server.middlewares.use((req, _res, next) => {
    const url = req.url.split('?')[0];
    const reserved = ['/src/', '/sites/', '/node_modules/', '/@'].some(p => url.startsWith(p));
    const isFile = /\.[a-z0-9]+$/i.test(url);
    if (!reserved && !isFile && url !== '/') req.url = '/index.html';
    next();
  });
}
```

**Production (Cloudflare Workers Static Assets):** add SPA fallback to `wrangler.jsonc`:

```jsonc
"assets": {
  "directory": "./dist",
  "not_found_handling": "single-page-application"
}
```

`index.html` runs `src/main.js`, which derives the site name:

```js
const siteName = location.pathname.slice(1).replace(/\/$/, '') || 'trung';
```

## Rendering pipeline

`scripts/snapshot.mjs` (Playwright + a tiny built-in static server, ~80 lines):

1. Parse CLI args: `node scripts/snapshot.mjs <site> [--watch]`.
2. Start a static file server rooted at the repo (so relative asset paths and `<link>` tags resolve under HTTP).
3. Read `sites/<site>/manifest.json`.
4. For each non-final page, in parallel batches of 4:
   - Launch headless Chromium at **portrait** (390×844, DPR 1.5), navigate to `http://127.0.0.1:<port>/sites/<site>/<page.html>`, wait for `domcontentloaded` then `networkidle`, screenshot to `sites/<site>/snapshots/<basename>.portrait.png`.
   - Repeat at **landscape** (1280×800, DPR 1.5).
5. In `--watch` mode, re-snapshot affected pages when files under `sites/<site>/pages/` or `sites/<site>/assets/` change.

Run via npm scripts:

```json
"scripts": {
  "dev": "vite",
  "build": "vite build",
  "preview": "vite preview",
  "snapshot": "node scripts/snapshot.mjs"
}
```

Typical dev loop: `npm run snapshot trung -- --watch` in one terminal, `npm run dev` in another, edit HTML, refresh browser.

## Runtime changes (`src/main.js`)

The procedural `PAGES = [...]` array is removed. Pages are loaded from a manifest at startup:

```js
async function loadSite(name) {
  const manifest = await fetch(`/sites/${name}/manifest.json`).then(r => r.json());
  const orientation = window.innerHeight > window.innerWidth ? 'portrait' : 'landscape';

  const pages = await Promise.all(manifest.pages.map(async (p) => {
    if (p.final) return { kind: 'final', html: `/sites/${name}/${p.html}` };
    const base = p.html.replace(/^pages\//, '').replace(/\.html$/, '');
    const img = await loadImage(`/sites/${name}/snapshots/${base}.${orientation}.png`);
    return { kind: 'snapshot', img };
  }));

  return { manifest, pages };
}
```

The existing `paint(p, w, h)` interface is wrapped: each snapshot page becomes `(p, w, h) => p.drawImage(page.img, 0, 0, w, h)`. Cloth simulation, tear logic, fall-and-advance — all untouched.

**Final-page handling.** Today's `enterStaticMode()` paints the final layer with a canvas function. New behavior: hide the GL/2D canvases and mount an iframe sized to the viewport, `src` pointing at the final page URL.

```js
function enterStaticMode() {
  staticMode = true;
  glCanvas.style.display = 'none';
  canvas.style.display = 'none';
  const iframe = document.createElement('iframe');
  iframe.src = pages[pages.length - 1].html;
  iframe.style.cssText = 'position:fixed;inset:0;width:100%;height:100%;border:0;';
  document.body.appendChild(iframe);
}
```

No sandbox attribute in v1 — local dev is trusted code. v2 (arbitrary user uploads) will add `sandbox="allow-scripts"` and serve the final page from an isolated origin.

**Orientation changes.** Today's `resize()` rebuilds the cloth on every resize. Extend it: when the viewport crosses the portrait↔landscape threshold, also re-fetch snapshot textures from the matching breakpoint set. No change to cloth simulation.

**404 handling.** If `fetch('/sites/<name>/manifest.json')` returns 404, render a minimal "site not found" message. No cloth, no GL.

## Migration plan

Port the 8 procedural pages from `src/main.js` to HTML+CSS in `sites/trung/pages/`. Each page is a self-contained HTML doc whose `<body>` fills the viewport with the page content.

Shared CSS lives in `sites/trung/assets/style.css`: the playful font stack (`"Marker Felt", "Comic Sans MS", ...`), polaroid frame, gradient text helper, sparkle pattern, wavy underline. Each page links it.

Order of work:

1. Build the runtime scaffolding first (manifest loader, snapshot script, routing). Stub `sites/trung/` with a single page so the pipeline can be validated end-to-end before porting all 8.
2. Port page 0 (hello/Trung). Compare snapshot to today's canvas output. Fix any CSS gaps before doing the next 7.
3. Port pages 1–7 in order. Visual diff against the deployed site at matching viewports.
4. Add `sites/demo-other/` with 2–3 trivial HTML pages (e.g. `<h1>Hello</h1>`-style) and verify `/demo-other` renders the cloth flow with no `src/main.js` changes.

If a CSS feature snapshots poorly under Playwright (custom fonts, blend modes, certain gradients), fix the CSS — don't fall back to canvas. The whole point is HTML fidelity.

## Test plan

- Side-by-side compare `localhost:5173/` against today's deployed site at the same viewports (portrait phone, landscape desktop). Tear behavior, page sequence, and content match.
- Visit `/demo-other` (a stub site). Cloth runs end-to-end with content unrelated to Trung.
- Resize across the portrait↔landscape boundary mid-tear. Textures swap to the matching breakpoint, simulation continues.
- `npm run build && npm run preview`. All paths resolve correctly under `/`, `/trung`, `/demo-other`.
- Visit `/nonexistent`. Renders a 404 message, doesn't crash.

## Out of scope — deferred to v2

- **Hosted SaaS flow**: editor → Cloudflare Browser Rendering → R2 + KV → short-link viewer. v1's local Playwright pipeline is the same shape; v2 swaps the snapshot step.
- **Sandboxed final-page iframe** for arbitrary user HTML.
- **Customization knobs**: cloth color, physics, sparkle density, breakpoint set.
- **Live editing** of an existing site / share link.
- **Auth, accounts, analytics, custom domains**.
- **Multiple final-page paths** (e.g. land on different pages based on which pin is torn first).
